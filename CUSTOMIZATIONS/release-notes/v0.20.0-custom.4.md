## v0.20.0-custom.4 (2026-10-09)

基于上游 marktext **v0.20.0 正式版**（tag `v0.20.0`）的第四个自定义版本。

> **本版是首个正式版（非预发布）**：基线已锚定上游正式发布 tag，编辑器内核回归稳定，因此不再标记 Pre-release。此前 `custom.1` ~ `custom.3` 均为预发布。

### 本版新增

**多目录工作区（Workspace 面板）**

侧栏新增第五个面板，提供类似 VSCode 的多根目录工作方式：

- **多目录并列**：一个窗口可同时打开多个文件夹，各自一棵可折叠的目录树；点 Markdown 文件进编辑器标签页（已打开则切回，不重复开），其他类型文件交给系统默认程序
- **`.mt-workspace` 配置**：版本化 JSON（`{version, name, folders, settings}`），支持**打开 / 保存 / 另存为 / 关闭**；目录增删**自动写回**配置文件；窗口级记忆，重启后自动恢复上次的工作区
- **最近打开**：工具栏「最近打开」下拉列出最近用过的工作区（最多 12 个，悬停显示完整路径，已失效的自动隐藏），可一键切换或清除记录
- **文件级右键菜单**：新建文件/文件夹、重命名、移到回收站、复制/剪切/粘贴、在资源管理器中显示；根目录另有添加/移除文件夹、保存/另存为
- 与现有「文件」面板**完全独立并行**：搜索、快速打开（Ctrl+P）、图片相对路径仍按原有单根逻辑工作，互不影响

### 修复与改进

- **修复 `.mt-workspace` 目录路径记录不可靠导致重新打开识别不到目录**
  - 此前把目录存成相对于工作区文件所在位置的相对路径。工作区文件集中存放、被引用的项目在别处时，文件一旦移动该基准即静默失效，重新打开后目录全部丢失
  - 现在**一律记录绝对路径**；读取时对相对路径（VSCode `.code-workspace` 风格）仍兼容，并在原基准解析不到时回退到卷根尝试，可自动救回此前写坏的配置文件
  - 另存为对话框的默认路径改为绝对路径（文档目录），避免对话框初始位置取决于进程工作目录

### 已知问题

- 未签名构建：Windows SmartScreen 可能告警，需手动允许；macOS 未公证，首次打开需右键 → 打开
- 工作区面板的树会**始终忽略** `node_modules` / `.git` / `.hg` / `.svn` / `*.asar`（否则递归读取不可用），其余文件（含隐藏文件）全部显示
- 未绑定配置文件时增删目录只改内存并显示未保存标记，需点「保存」触发另存为落盘
- 同一目录若同时在「文件」面板与「工作区」面板打开，会各挂一个目录监视器（功能正常，开销可控）
- `preserveFormattingOnSave` 的原文回放作用于**顶层块**：编辑表格某个单元格后，整个表格会按规范重排（未被编辑的表格不受影响）；「源码模式」不受此机制影响
- 数学偏好不向后兼容：旧配置项 `math` 与「GitLab 兼容」开关已被 `texMath*` 系列取代，升级后需按需重设
- 本机（Windows）发布前检查实测数字（环境相关，与本次改动无关的浮动忽略不计）：
  - desktop 单测 `pnpm run test` **985 通过 / 0 失败 / 36 跳过**
  - `pnpm run lint` **0 error**（172 warning 为上游既有基线）；`pnpm run typecheck` 通过；`pnpm run build:unpack` 通过
