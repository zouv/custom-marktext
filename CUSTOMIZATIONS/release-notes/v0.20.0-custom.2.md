## v0.20.0-custom.2 (2026-09-15)

基于上游 marktext develop@1d3025b2（0.20.0 开发线）的第二个自定义版本。

> 预发布说明：基线是上游 develop 分支提交（非正式 tag），功能未经完整回归，建议先在非关键环境使用。

### 本版新增

- **侧栏第四面板「当前目录」（CUSTOM-20260909-001）**
  - 快速浏览 / 切换**当前打开文件所在目录**下的 Markdown 文件，无需 Open Folder 打开整个项目树
  - 零新增 IPC，全部复用现有原语：`window.fileUtils.readdir` + `hasMarkdownExtension` + `window.path`（pathe）
  - 点击打开与左侧文件树同构：tabs 中已打开则切换（不新开标签），否则走 `mt::open-file` 完整链路新开
  - 当前文件高亮跟随；切换文件导致目录变化时自动重载，另有手动刷新按钮
  - 状态文案覆盖五种情况：加载中 / 空目录 / 未保存文件 / 读取失败（可重试）
  - 刷新策略为 v1 拉取式（切文件重载 + 手动刷新），未挂文件监听；实时性需求出现再做 v2

### 修复与改进

- **补齐历史欠账的界面文案**：locale parity 测试强制 11 种语言键一致，本次补上 `preferences.markdown.lists.preserveFormattingOnSave`（9 语言）与 `menu.window.resetZoom`（nl）；parity 测试从 9 失败 → 35/35 全绿
- **恢复 `editor.vue` 被 Prettier 误伤的格式**：CUSTOM-20260904-004 提交时 `prettier --write` 顺带把 5 处函数声明改成了无空格写法（`constructor (` → `constructor(`），与仓库 ESLint 规则冲突，导致 `pnpm run lint` 报 5 个 error。本次恢复上游写法，lint 从 5 error → **0 error**；该文件与上游的 diff 也收敛为仅 `[CUSTOM-BEGIN]` 标记块，后续合并更干净

### 已知问题

- 未签名构建：Windows SmartScreen 可能告警，需手动允许；macOS 未公证，首次打开需右键 → 打开
- `preserveFormattingOnSave` 的原文回放作用于顶层块：编辑表格某单元格后整个表格按规范重排（非编辑表格不受影响）；「源码模式」不受此机制影响（本就原样保存）
- 本机（Windows）运行 `pnpm run test` 实测 **761 通过 / 11 失败**，均为环境相关基线、与本次改动无关：
  - 7 个来自上游 `move-image-to-folder.spec.ts`——硬编码 `'assets/'` 前缀断言，而 win32 下 `path.relative` 产出 `assets\pic.png`（反斜杠），该 spec 为 POSIX 专用
  - 4 个来自 `pdf.spec.ts` 在整包并发下的 5s 超时，隔离重跑即通过（浮动）
  - 二者在 Linux CI 上均通过，不影响本页构建产物
